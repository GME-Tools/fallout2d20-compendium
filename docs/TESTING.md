# Testing and release checks

## Everyday validation

Use Node.js 20 or 23 for repository tooling:

```sh
npm ci
npm run ci
```

`npm run ci` is the authoritative local gate. It validates artwork and source
documents, audits bilingual content and French weights, runs the tests, builds
all Foundry v14 LevelDB packs, packages the module, and verifies both generated
packs and the ZIP. Outputs are `packs/` and `dist/`; neither is source.

Useful focused commands:

- `npm run source:materialize`: rebuild disposable readable EN/FR JSON views
  from the canonical documents and language overlays.
- `npm run validate`: schemas, identities, links, provenance and diagnostics.
- `npm test`: regression suite without rebuilding.
- `npm run audit`: untranslated text and extraction bleed.
- `npm run audit:weights`: exact French `kg = lb / 2` checks.
- `npm run artwork:inventory`: refresh the reviewed inventory and contact sheet.
- `npm run build`: rebuild LevelDB packs.
- `npm run package`: create the installable archive.

Validation must be warning-free. Reviewed inventories are manual inputs and are
never regenerated by `audit`, `validate`, or `ci`. Tests lock the released V1
identity set, categorical bilingual packs, publication provenance, canonical
reprints, UUIDs, artwork decisions, translations, recipes and runtime behavior.

## Foundry smoke test

Use a dedicated or disposable world, never a user world. Close Foundry before
rebuilding the installed `packs/` directory.

At minimum:

1. Enable the module on the release's Foundry/Fallout matrix.
2. Confirm both language folders and all expected packs appear.
3. Open representative Items, Actors and RollTables.
4. Import and exercise documents affected by the current change.
5. Check UUID links, embedded Items, sheets and table draws.
6. Record genuine editorial ambiguity in `docs/EDITORIAL-DECISIONS.md`.

For compilation without replacing installed packs (materialize sources first
when invoking the compiler directly):

```sh
npm run source:materialize
node scripts/build-packs.mjs --output /tmp/fallout2d20-packs
```

For an installed server and isolated world, set `FOUNDRY_APP_PATH`,
`FOUNDRY_DATA_PATH`, and `FOUNDRY_WORLD`, then run `./ci/run_headless_validation.sh`.
It binds to loopback and fails on startup errors or missing embedded records.
Foundry 14.367 requires Node 24.13.1 or later for its server; this is independent
of the repository's Node build matrix.

Browser validation is available through `ci/run_foundry_browser_validation.mjs`
with external Playwright. `ci/run_foundry_us106_validation.mjs` retains the
specialized capacity and multi-client language regression. Both target only the
isolated smoke server.

## Release

Before tagging: run full CI once on the final tree, complete the current/prior
Foundry-Fallout smoke matrix, review changed artwork, and satisfy Oracle or
record an owner waiver. Update versions and release notes coherently. Tag and
publish only with explicit owner authorization, then verify GitHub CI, the
release workflow, ZIP and `module.json` assets.
